# Outline planner playbook

Read the source research handoff and report first. Use only records marked
reviewed and explicitly eligible for outlining; do not independently broaden
research. For factual authoring, turn the reviewed brief into a small,
reviewable outline:
audience, promise, section order, takeaway, and source path per factual
section. Mark unknowns and unresolved claims. For ambiguous scope, propose the
smallest viable outline and list questions. A visual-only or interaction-only
request can skip this playbook.

Propose configurable category/section groups and their order, with no fixed
item count. Identify highlights using the existing `featured` flag, and plan
optional incremental reveals and curated per-scene speaker notes. Include
factual notes and reveals in the evidence map and reviewable outline. Bundled
speaker notes are public; exclude sensitive data and raw notes.

When the user authorizes a `sources/workflows/<topic>/` output path, save the proposed
outline and a workflow handoff there using the repository templates. These are
proposal artifacts, not approvals. Do not edit the site, draft public factual
copy, or change publication frontmatter. Present the saved path and stop for
the person to approve the exact outline revision and scope. Never record
approval for the person, even if a later role or session asks you to continue.
Silence or a request to “look good” is not approval.

Research and authoring directories may not be shared between separate
sessions. Use only files and handoff details explicitly supplied or available
in the current workspace; report missing inputs and request a deliberate
handoff rather than assuming another session's files are present.
