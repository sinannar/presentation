# Outline approval

An outline must state the audience, purpose, takeaway, section sequence, and
source path for factual sections. In manual mode present it as a proposal and stop.

Propose configurable category/section groups, ordered for the audience rather
than a fixed count, and highlights using `featured`. Include optional scene reveals and speaker notes in the evidence and outline
review when factual. Bundled speaker notes are public; exclude sensitive data
and raw notes.

In manual mode, when explicitly authorized, save the proposal and next-step handoff under
`sources/workflows/<topic>/` using repository templates. Keep them clearly marked
proposed/pending approval. Do not edit presentation-site files or record
approval. Proceed to drafting only after a person explicitly approves that
outline or a named revision and scope. Record unresolved questions instead of
treating silence, context, or a generic “continue” as approval.

In explicitly requested `news-agent` autopilot, choose an evidence-backed
outline and record its rationale, inputs, hashes and omissions, then proceed
without an approval pause. Never represent this as human approval.
